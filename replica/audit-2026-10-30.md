# End-to-end audit, 30 October 2026

What was checked: every customer screen in the app, every customer web page, every admin section and the editors
each one opens, the API's access rules, and the security of the running server. Everything found was fixed in this
pass and checked again. Severity follows the UX gate scale: S1 blocks a task or exposes data, S2 a serious problem
with a workaround, S3 friction, S4 polish.

## How it was checked

| Area | Method | Result after fixes |

## Findings and fixes

| # | Sev | Where | What was wrong | Fix |
|---|---|---|---|---|
| 1 | S1 | Web checkout | Delivery orders could never be placed from the website. The page sent a typed address, but the server only takes a saved address with a delivery area. Every delivery order ended in "Choose a delivery address". The browser tests that should have caught it were not part of `verify.sh` | Checkout now lists saved addresses and adds a new one with its delivery area, as the app does; the area's fee and minimum order show; Place order waits until an address is chosen. The browser flows now run in `verify.sh` |
| 2 | S1 | Ordering API | When the same order was sent twice at the same moment (a double tap, a network retry), the second request waited for the first, found the cart already emptied and answered "Your cart is empty", although the order had been placed | After taking the cart lock the server looks for the order again and returns it. New test `two requests with the same key at the same moment both get the one order` fails without the fix and passes with it |
| 3 | S1 | Staff sign-in | No limit on wrong passwords: 12 guesses in a row were all answered. The staff password is shared, so it could be guessed | Failures are counted per source (stored as a hash) and in total over 15 minutes: 10 per source, 100 overall, then 429 "Too many wrong passwords". New table `staff_login_failures` (`db/security.sql`), test `staff-login.test.ts` |
| 4 | S2 | Customer app, large text | At 140% text the home carousel, category tabs and membership tiles overflowed their fixed heights | Those rows now grow with the text size (`scaledHeight`) |
| 5 | S2 | Customer app | The compact quantity stepper and the category chips were 44 points tall, below the 48 point tap target | Both are 48 points |
| 6 | S2 | Customer app | Brand-colour text on the light brand tint measured 4.25:1, below 4.5:1 | A darker shade of the brand colour (`accentInk`) is used on tints; for any brand colour the admin accepts it is at least about 6:1 |
| 7 | S3 | Customer app, assistant | A suggested question named "the grilled chicken plate", a dish only the sample restaurant has | The suggestion uses a dish from the restaurant's own menu, or a general question when there is none |
| 8 | S3 | Admin, partners | Making a key on a server without `PARTNER_KEY_SECRET` showed a bare server error (500) | A clear message: partner keys are not set up on this server yet (503). The server still refuses to make keys without the secret |

## Checked and holding

- Every `/v1/admin/*` route and method answers 401 without a staff session.
- Guest B gets 404 for guest A's order, cannot price, order to or delete A's saved address, and sees none of A's
  addresses. The order page itself is a shell; its data comes from the API, which refuses.
- The guest cookie is `Secure; HttpOnly; SameSite=Strict`. The staff cookie is `HttpOnly; SameSite=Strict`, and `Secure`
  in production.
- Content Security Policy, `X-Frame-Options: DENY`, `nosniff`, a strict referrer policy, no `X-Powered-By`.
- Media paths with `../` are refused. A 3 MB body and broken JSON get a 400 with a clear message.
- No `dangerouslySetInnerHTML` or `innerHTML` anywhere in the web or admin code; all SQL uses parameters.
- Logo upload checks the file's real type and caps it at 1 MB (`branding.test.ts`).
- Row-level security tests: 8 of 8.

## Known limits, not defects

- **Arabic contrast flags in the app sweep (12, all Arabic, all on near-white backgrounds).** Flutter's contrast
  check samples pixels inside each label. Thin Arabic strokes leave it too few solid pixels, so it reads the
  background as the text colour (ratios like 1.08:1). The colours used are the same as in English, which passes:
  text 17.5:1, muted text 7.6:1, brand on white 5.0:1, brand ink on tint about 6:1.
- **Admin map tiles** do not load in this sandbox because outbound access to the tile server is blocked. Zones,
  fees and minimums still save and are covered by tests.
- **APK build** still waits on Maven Central, which answered 429 from this environment.
